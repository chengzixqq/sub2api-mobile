骨架已经按你的选择定好（A 的结构 + B 的键盘 + 你改的日志行，Tab 叫“概览 · 账号 · 用户 · 监控”）。这一轮在主模式里比细节：外观质感、首页营收和待处理、账号分组和行样式、详情操作位置、用户页、请求详情。每题的手机都能点；右上角切深色。第 1 题“外观”是全局的，选一套用于所有页面，建议点进账号详情一起看。

Q1

主模式整体用哪套外观？（一套用于所有页面）

三台手机布局完全相同，只换外观。选中的一套会用到所有页面，不能首页一套、详情另一套，所以请首页和详情两屏一起看再选。先看首页，再点「受限 2 个账号」→「Claude-官方-03」进账号详情，看状态卡、倒计时、按钮行和容量条。也可以切到「监控 → 告警」看小按钮的主次，或进「用户 → 王小明 → 充值」看大数字键盘。最后在顶部切到深色再看一遍。注意：B 式柔和在真机上的数字是 SF Pro Rounded 圆体，网页预览（Windows Chrome）显示不出圆角，只能在真机或 Mac Safari 上看到；预览里 B 式柔和和折中的数字只差字重和字号。

Q2

首页的营收区放哪、放多大？

先看第一屏：营收和待处理谁排在前面、营收占多大地方。三个选项的待处理都用现有的合并方式（粒度在第 2 题定）。再往下滚，看用量和“更多统计”入口在哪。图例只标“今天 / 昨天”两条线；成本、标准、差额只写文字，不配色标。

Q3

待处理按什么粒度列？

三部手机的异常数据一样：标准组有错误、过载、临时不可调度各 1 个账号，并且在告警；高级组有 1 个账号限流；GLM-直连-01 同时属于标准组和默认组（跨组账号）。看同一件事会不会被报好几次，每个问题要点几下才能处理完。可以试试点“恢复状态”、分组卡标题和卡里的告警。

Q4

没有任何异常时，首页要不要换一种布局？

两部手机都假设没有任何异常（只改了首页的演示数据），营收区都按第 1 题的“顶部一行”演示。选 1：第 1 题定了哪种营收布局就一直用哪种，没事时只把待处理收起来；选 2：没事时换成一屏专门看营收和用量的布局，有事再切回第 1 题的布局。注意：选 2 时首页会在“有事”和“没事”之间换结构。

Q5

（第 3 题选 1 时）没事时待处理收成什么样？

只有第 3 题选“布局不变”才需要定这一题。两部手机都是没有异常的状态，营收区都是“顶部一行”，只比较待处理那一块。

Q6

账号列表按什么分组？

看三点：一打开能不能先看到出问题的账号；把所有组收起后，能不能当总览看；找某个平台、某个分组或今天金额最高的账号快不快。这一题的行样式都是三行，行样式下一题再挑。这 4 种也可以都放进右上角菜单，在 App 里随时切换，这一题只定默认用哪种。

Q7

账号行长什么样？

三个选项都在“按紧急程度”分组下比较。看一屏能显示几个账号，异常原因和恢复时间还看不看得到，金额是否方便比较。这一题可以和上一题任意搭配。

Q8

账号详情的操作放哪？

三台手机都是限流账号 Claude-官方-03，下方信息都全部展开，整页约 3 屏。先往下滚到“最近请求”“定时测试”，再试着去点“恢复状态”；然后点右上 ⋯ 看看菜单。点左上返回可以换其他账号：错误账号 OpenAI-备用-A（恢复并启用调度）、暂停账号 Gemini-测试-B（启用调度）、停用账号 Grok-旧-01（启用账号）、正常账号 Claude-官方-01（测试连接）。

Q9

账号详情下方的信息怎么组织？

三台手机都是限流账号 Claude-官方-03，操作都用按钮行。三种组织方式的内容完全一样（容量、上游用量窗口、今日、每小时实际扣费、请求记录、最近请求、定时测试、档案、可用模型），只比怎么摆。可以往下滚、切换分段、展开或收起卡片，再点进一条请求后返回：三种方式都会记住你刚才看到的位置。也可以点左上返回，换正常账号 Claude-官方-01 或暂停账号 Gemini-测试-B，对比内容较短的页面。

Q10

用户详情的头部用哪种？

看三点：余额和充值按钮是不是一眼就能看到；一屏能看到几笔流水；充完值新的一笔落在哪。可以这样试：点「充值」→ 按 5、0 → 提交 → 确认。钱包卡和 A 的新流水在 API Key 下面，要往下滑才看得到；紧凑头部的就在最上面。三种的数据和安全规则一样：流水来自 balance-history，显示类型、金额、时间、备注，后端不返回变动后余额，所以不写“余额 $X”。用户有待核对的充值时，「充值」降为次按钮，点了先问「先核对 / 仍要充值 / 取消」。可以点返回，进周婷（待核对）、李娜（余额低）、赵磊（禁用）看提示。

Q11

用户列表的每一行用哪种？

看两点：扫一眼能不能分清谁余额低、谁待核对、谁禁用（不能只靠颜色）；金额好不好上下对齐着比。两种都能点进用户详情。余额低按阈值实时计算（对应用户的 balance_notify_threshold），充值后标记会自动消失。

Q12

用户列表顶部要不要一排快捷充值头像？

这题下面的列表都用 A 两行列表。上一题如果选了右侧固定列，这里只是行换一下，结论不变。可以这样试：点李娜的头像 → 按 5、0 → 提交 → 确认，看她头像的琥珀圈和列表里的“余额低”会不会消失；点周婷（待核对）会先进详情去核对，不会直接打开键盘。

Q13

成功请求的详情页用哪种？

看同一条成功请求（09:41 claude-sonnet-4-5，流式）：实际扣费、首字/耗时、Token、三口径成本、用户/Key/分组/账号怎么排。可以点用户、账号，也可以返回列表点别的成功记录（09:40 gpt-4.1-mini 是非流式，没有首字）。成功页和失败页可以选不同的方案，最后按两题各自的选择组合。

Q14

失败请求的详情页用哪种？

看同一条失败请求（09:39 glm-4.6：第 1 次 529，第 2 次超时，客户端收到 504）：错误原文、重试链和“标记已处理”。可以先点“标记已处理”，再去看账号或某次尝试，返回后标记还在。也可以回列表看“上游错误”里 429 那条（换账号重试成功），以及“错误请求”里 09:30 的 400（客户端参数错误）。这题可以和上一题选不同的方案。
