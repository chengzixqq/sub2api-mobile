# 写一个新布局预览的工程约定

本目录用来做可点击的 HTML 原型：每个布局一个页面，平铺 6–8 台 iPhone，每台都能点。新布局只新增自己的文件，**不改任何共享文件**。

## 你要新增的文件（`<key>` 由任务给定，例如 `fx-duty`）

| 文件 | 内容 |
|---|---|
| `layouts/<key>.jsx` | 全部组件和页面；头部注释里写一行 `@title 名称`（页面标题） |
| `layouts/<key>.css` | 样式；所有选择器挂在 `.lay-<key>` 之下，不能污染其他布局 |
| `layouts/<key>.verify.cjs` | 交互检查：`module.exports = [[说明, async (ph, page) => {...}], ...]`，`ph(i)` 是第 i 台手机（Playwright locator） |

不要修改：`shared/*`、`build.cjs`、`verify_previews.cjs`、`tools/*`、其他 `layouts/*`、`directions/*`、`index.html`。

## 构建与检查（在本目录执行）

```bash
node build.cjs <key>                                              # 生成 <key>.html（离线单文件）
PW=C:/Users/Administrator/AppData/Local/Temp/sub2-pw/node_modules/playwright-core
D=G:/weixinProject/sub2-mobile-native/docs/ui-reassessment-claude-20261016/html-preview
node verify_previews.cjs "$PW" <key>                             # 跑 layouts/<key>.verify.cjs（浅/深各一次）+ 整页截图 → screenshots/<key>-*.png、verification/<key>.json
node tools/shot.cjs  "$PW" "$D" <key> light out.png              # 整页截图，并打印页面报错
node tools/phone.cjs "$PW" "$D" <key> dark 3 out.png [操作...]    # 第 3 台手机特写（1.5x），可先执行操作：
                                                                  #   CSS 选择器 → 点击；"text:充值" → 点第一个含该文字的元素；"scroll:.选择器:300" → 滚动
```

截图后**用 Read 工具打开图片亲眼检查**，浅色、深色都要看，至少每台手机看一次特写。临时截图放到 `$TEMP` 下，不要堆在本目录（`screenshots/<key>-*` 由 verify 生成，可以留）。

## 运行环境

- 所有 jsx 拼成一个脚本，Babel 编译，React 18 UMD 全局可用（`React.useState` 等；`shared/core.jsx` 顶部已有 `const { useState, useEffect, useRef } = React;`，**不要重复声明**）。
- **顶层标识符必须带你自己的前缀**（例如 `Fd` / `fd`），因为会和共享文件同处一个作用域，重名会直接报错。
- 不能用网络、不能引外部字体或图片；图标用 `Icon`，图表自己用 SVG 画。

**样式（`shared/base.css` + `shared/vernier-palette.css`）**
- 配色只用 `.pal-vernier.light/.dark` 提供的变量：`--canvas --surface --sunken --track --hairline --rule-strong --ink1 --ink2 --ink3 --accent --accent-fill --on-accent --accent-wash`，语义色 `--ok/--caution/--critical/--neutral/--model` 及其 `-ink`、`-wash`，口径 `--lg-actual --lg-cost --lg-standard`，玻璃 `--glass-bg --glass-edge --glass-shadow`，以及 `--tab-*`、`--hover*`。**不要自造新颜色**（阴影透明度可以）。
- `.tone-ok/.tone-caution/.tone-critical/.tone-neutral/.tone-model` 会设置 `--tone --tone-ink --tone-wash`。
- **状态胶囊**（用户评审 2026-10-18 第 3 条，主模式全局）：每条消息 / 模块左侧的状态色是一根**浮在左侧的细长胶囊**，不是贴边竖线。规格：宽 `--rail-w` 4px、离本条左边 `--rail-inset-x` 6px、离本条上下边 `--rail-inset-y` 各 10px、两端全圆角（半径 = 宽 / 2）、颜色 `var(--tone)`；内容左内边距不小于 `--rail-clear`（16px），文字不压到胶囊；同一张卡里叠放的多条各画各的，彼此不相连。写法：给“一条”（行、状态卡、横幅、卡片、表格首列）加 `.tone-rail` + 一个 `.tone-*`；核心 `skin.rowClass(tone)` 给的 `.rail` 在 `.lay-main` 下画的也是它（`shared/base.css`「状态胶囊」节，画在 `::after` 上；`::after` 已被占用的元素用同样的 `--rail-*` 变量自己画，例如 v-user-edit 的未保存 / 有误标记）。胶囊**不改本条的底色**：状态横幅一律是“`--tone-wash` 底色 + 胶囊”一种样子，`.banner` 带 `.tone-caution / .tone-critical / .tone-model` 时自动画胶囊（与 `rowClass` 给 `.rail` 的三种色一致，不必再加 `.rail` / `.tone-rail`，也不要再单独补 `background`），ok / neutral 横幅不画。胶囊颜色只取 `.tone-*` 给的语义色（不能 `.tone-*` 时写 `--tone: var(--neutral)` 等语义变量，不用 `--ink3`）。行首元素不许用负外边距伸进胶囊区：`.lay-main` 下头像行的头像列从 16px 起、列宽 26px，正文和分隔线从 52px 起（同一列表有没有胶囊的行都对齐）；带胶囊的日志行状态码徽章不再左移。**不要再写** `border-left`、横向 `inset` 阴影、`linear-gradient(to right, var(--tone) 0 3px, …)`、贴边或贴顶的 3px 伪元素。SwiftUI：`.overlay(alignment: .leading) { Capsule().fill(tone).frame(width: 4).padding(.vertical, 10).padding(.leading, 6) }`。
- 已有的通用类：`.screen .scroll .nav .glass .glass-btn .tabbar .tabs .tab .tab-search .toast .sheet .dialog .chip .seg .submit .search-field` 等，可以复用，也可以在 `.lay-<key>` 下覆盖。
- `.row-meta` 是单行 flex（各段之间 4px）。flex 盒子画不出省略号，所以：**纯文字的 `.row-meta` 自动变成块级、超长时出“…”；由几段组成的（时间 + 备注、图标 + 文字）由最后一个 `<span>` 省略**（徽章除外）。想让最先被截的那段在最后，就把它放在最后一个 span 里；需要换行的另加类写 `display:block; white-space:normal`（如 `.mo-wrap`）。

## 主模式变体（layouts/main/）

主模式 = A 收件箱骨架 + 已定决策（见 `../DECISIONS.md`），源码 `layouts/main/00-core.jsx`、`00-core.css`、`zz-mount.jsx`。待定的选择用“变体槽”比较：

- 槽：`today`（今日整屏）、`accounts`（账号列表整屏）、`accountRow`（账号行）、`accountDetail`（账号详情整屏）、`users`（用户列表整屏）、`userDetail`（用户详情整屏）、`logRow`（日志行）、`request`（请求详情整屏）。每个槽的 `base` 是当前已定实现，在 00-core.jsx 里。
- 新变体写在**你自己的** `layouts/main/v-<名字>.jsx`（可配 `v-<名字>.css`），用 `mvRegister('槽名', '变体名', 组件)` 注册；组件收到的 props 与 base 相同（`{ctx}`、`{ctx, a}`、`{ctx, id}`、`{ctx, l}`）。可以复制 base 组件再改。顶层标识符必须带你的前缀。
- 也可以读自己的开关：手机的 `initial.v` 会原样出现在 `ctx.v`（例如 `ctx.v.homeRevenue`），一个变体组件可以按开关画出多种样子。
- 外观类变体：`ctx.v.vis` 会变成 App 根节点的类名 `vis-<名字>`（默认 `vis-base`），在 CSS 里写 `.lay-main.vis-<名字> …` 覆盖样式。
- **新页面**：任何 `stack` 项 `{kind: 'X', ...}` 都会渲染槽 `screen:X`（组件收到 `{ctx, route}`，route 就是这个 stack 项）；任何 `sheet` `{kind: 'Y', ...}` 都会渲染槽 `sheet:Y`（组件收到 `{ctx, sheet}`）。用 `mvRegister('screen:X', 'base', Comp)` 注册默认样子，再注册替代样子（例如 `'tabs'`），手机用 `initial.v['screen:X'] = 'tabs'` 选择。没注册的 kind 显示“下一轮出对比”的占位页。
- 已接好的入口（kind）：`analytics`（概览首页“更多统计”、搜索目录“统计分析”）、`accountNew`（账号页右上 +）、`accountEdit`（带 `id`；**已定的账号详情就是内联编辑页（`accountDetail:'inline'`），它的 ⋯ 里没有“编辑账号”**，单独的编辑表单只在对比页的 `screen:accountEdit` base / seg 和 base 详情的 ⋯ 里出现，不要把它当主入口写路由）、`groups`（搜索目录“分组”）、`redeem` / `proxies` / `announcements`（搜索目录）、`userNew`（用户页右上 +）、`userEdit`（用户详情 ⋯ → 编辑用户，带 `id`）、`alert`（待处理里的告警项、监控 · 告警的每一行，带 `id`，核心已有 base）。你新增的二级页面自己起 kind（例如 `group`、`analyticsMore`），用 `ctx.push({kind, ...})` 进入。
- 删除确认用 core 里的 `confirmDelete(ctx, '账号', name, onDone, {remove?, typed?, message?, match?, label?, placeholder?, caseInsensitive?})`：标题写对象，正文第一行写站点，`message` 写删除后果（单独一行，跟在站点行后面，例如用户的“名下 2 个 Key 一并删除。”——后端删除用户会一起删掉他的 Key）；Face ID 关闭时要**输入完整名称**才能点删除，打开时按钮是「用 Face ID 删除」；`onDone`（通常是 `ctx.pop`）先执行，`remove` 再真正删除（账号不传 `remove` 时按名称自动 `ctx.removeAccount`，其他对象请自己传）；`typed` 或 `initial.v.deleteTyped:true` 预填（预填的是 `match`），冒烟里用它演示“输对后删除”。兑换码的“输入末 4 位”可以并进来：`match` 传末 4 位，`label` / `placeholder` 换成“输入末 4 位确认删除”，`caseInsensitive: true` 让大小写都算对。返回上一页用 `ctx.pop()`。

- 隔离构建：`node build.cjs main--v-today+v-accounts+v-users+v-decided+v-<名字>` 只编译 core + 已定变体 + 你的文件，生成同名 html，并行时不会被别人的半成品打断。**一定带上 `v-today+v-accounts+v-users+v-decided`**：已定的首页、账号列表、用户页在这几个文件里，不带它们看到的是 base 样子，和 main.html 不一致。全部完成后由主线合成 `main.html`。

- 冒烟：`node tools/smoke_main.cjs "$PW" "$D" <页面 key> light|dark - "<状态名正则>"`，状态来自 `tools/routes/*.json`（每个负责人一个文件）和第 2、3 轮对比页。**每次点击都做落点审计**：点击是强制的，所以先把目标滚进视图，再看点击坐标（目标中心）上最上层的元素——必须是目标或目标的子孙，或者和目标属于同一个控件（文字匹配到按钮 / 胶囊里的 span 时，控件自己的 44pt 点按区 `::after` 盖在 span 上，算点中；嵌在目标行里的另一个按钮不算）。被 Tab 栏、sheet、确认框挡住，或 `text:` 先匹配到被遮住 / 隐藏的同名文字，都会记为失败并写明点到了什么。写路由时：Tab 栏会盖住屏幕最底部约 100px，目标在那里就先 `scroll:` 到上面；同名文字用更具体的 CSS 选择器（如 `.dialog button:has-text("…")`）。

## 文案与语义硬规则

- 账号状态词与 Web 一致：错误、过载中、限流中、临时不可调度、暂停、停用、正常（账号的启停对是「正常 / 停用」）；动作：启用调度 / 停止调度、恢复状态、测试连接、刷新令牌；凭据失效时的修复动作是「更换 API Key…」/「重新授权…」。不显示原始枚举。
- 恢复统一一个动词“恢复状态”（后端 `recover-state` 一次清除错误、限流、过载、临时不可调度、模型限流）。错误账号恢复后仍处于暂停调度，需要“恢复并启用调度”或单独“启用调度”。
- 告警没有“确认/ack”，只有“手动解决”和“静默…”。
- 可逆操作（调度开关）直接执行 + 回执里给“撤销”；资金操作必须二次确认，写明对象、站点、金额；不给默认金额。
- 缺失值显示 `—`，0 显示 0；金额不用红绿表示涨跌；计费数字不着色。
- **“计费”**（2026-10-18 评审第 4 条，用户确认统一叫“计费”）：原来的“营收”一律改叫“计费”——统计分析的“计费趋势”卡、“计费明细”单图页（原“营收明细”）、更多图表 / 分段里的“计费”主题，首页 B 式卡片的“今日计费”区；界面上不再出现“营收”。逐段的利润另有“利润明细”（实际扣费 − 账号成本，按小时 / 按天柱图 + 明细表：实际、账号成本、利润），与“计费明细”并列，卡底都写“全部 N 小时 / 天 · <页面名> ›”。
- **首页 6 格**（2026-10-18 评审第 1、2 条）：今日实际扣费、请求、错误率、利润、RPM、TPM，依此顺序 3 × 2；标签只写名字，**不写“近 5 分钟”等窗口后缀**（口径不变：今日实际扣费、请求、利润是 00:00 起，错误率、RPM、TPM 是近 5 分钟）；没有“健康”格。点 RPM / TPM 进统计分析 `{kind:'analytics', focus:'perf', metric}`，其余 4 格进统计分析。
- **状态胶囊**：带状态色的“一条”左侧一律是浮在左侧的细长胶囊（宽 4、离左 6、离上下各 10、两端全圆角、颜色 `var(--tone)`、内容左内边距 ≥ 16），规格与写法见上文“样式”节；不写贴边竖线。
- **“利润”**（第 2 轮用户原话）= 实际扣费 − 账号成本，所有页面都叫“利润”，不叫“差额”“毛利”；金额前不加“+”，亏损时照常显示“−”。数值用 `profitOf()`。“实际扣费”“账号成本”“标准”三个口径名保持不变。
- 颜色只表达状态，品牌青只表示“可操作 / 已选中”。
- 正文中文 ≥ 14px、标签 ≥ 12px；可点区域 ≥ 44×44（core 已给 `.chip` `.seg-item` `.act-small` `.toast-undo` `.kp-pill` `.large-title` 加了透明的 44 高点按区，画出来的高度不变）；对比度 ≥ 4.5:1（危险按钮用 `--critical-wash` 底 + `--critical-ink` 字，不要再用 #FF3B30 底白字）。
- 用户状态词：「启用 / 禁用」（同 Web：档案、筛选、徽章都写这两个字；句子里可写“已禁用”“已启用”）；账号状态词：「正常 / 停用」；「停用」也用于分组、代理、Key 等，但不用于用户，用户也不写“正常”。
- 设计要能用 SwiftUI（最低 iOS 26）实现：玻璃只用于 Tab 栏、工具栏、浮层；内容层不透明；列表必须能落到 `List`（滑动操作、多选）。
