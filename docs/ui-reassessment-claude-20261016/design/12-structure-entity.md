## 0. 一页摘要

**核心主张（一句话）**：把 Sub2 管理端变成一张“可导航的对象图”——账号、用户、分组、API Key、请求、错误、渠道、告警都是有身份、有统一对象页、有固定动作、可被全局搜索一步直达的“对象”；首页只是“需要关注的对象”的收件箱，Tab 只是对象集合的入口。

七个关键决策：

1. **一个导航值**：全 App 只用一种可导航值 `Route`，其核心是 `EntityRef(kind, id, 快照)`。任何屏幕上出现的对象名都是链接，点进去永远是同一张对象页。
2. **一副骨架**：每类对象一张对象页，固定为“摘要头 →（问题条）→ 主操作 → 分段 → 属性 → 关系”；每类对象一种列表行（状态先行、最多三行）。`Form` 只用于编辑，不再承载只读数据。
3. **动作挂在对象上，不挂在页面上**：每类对象有一张动作注册表（动作 × 状态条件 × 风险级别 × 摆放位置）。账号不论出现在收件箱、搜索结果、分组成员还是日志关联里，长按/滑动出现的都是同一组动作。这是救火速度的主要来源。
4. **全局搜索是一等公民**：`Tab(role: .search)` 承载跨对象搜索（邮箱、账号名、请求 ID、Key 片段、编号），其空状态就是“置顶 / 最近 / 浏览全部对象类型 / 在 Web 中管理”。低频模块不再需要“管理”Tab。
5. **管理员 Tab = 概览 · 账号 · 用户 · 监控 + 搜索**，与用户确认的四个高频任务一一对应；日志不占 Tab，但从每个对象的“关系”与搜索两步可达。Tab 集合由“角色 + 站点功能开关”在 Sub2Core 中纯函数推导，vendor 与普通用户各有自己的集合。
6. **一个操作宿主**：`ActionHost` 统一承担四级确认、二次验证、提交、结果反馈。全局同一时刻最多一张 sheet，新步骤在当前 sheet 内 push，永不叠 sheet。
7. **界面不再是验收面板**：骨架组件不提供“脚注/说明”插槽；口径说明只能经 `HelpTip(topic:)` 进入集中注册表；UITest 断言状态码而不断言中文文案；契约迁入 Sub2Core 展示层测试，并用文案 lint 阻断回流。

## 1. 核心主张与根治逻辑

### 1.1 三条公理

| 公理 | 含义 | 在界面上的可见结果 |
|---|---|---|
| **对象有身份** | 每个业务实体有 `EntityRef { kind, id, snapshot }`。`snapshot` 携带名称、主状态、副标题，跳转时随行带入 | 关系、筛选条件、搜索结果、收件箱条目都以**名称 + 状态**呈现，不再出现“用户 #8”“账号 ID 9”（`01 D13`、`RequestLogsView.swift:120`） |
| **对象有骨架** | 同类对象只有一张对象页、一种行、一张动作表 | 同一账号在列表、详情、搜索里说法一致（修 `01 D09/D10`） |
| **对象可达** | 任意对象：搜索 ≤2 步直达；任意出现处可点；任意对象都能看到“与我相关的记录/统计” | 日志不必占 Tab；“异常账号 1”可点（修 `01 D22`）；“统计分析”只有一个页面，靠作用域区分（修 `01 D23`） |

### 1.2 把思路推到极致的地方

- **待核对的写操作也是对象**（`pendingOp`）：出现在收件箱、可被搜索、有对象页（核对、重试原请求、标记已在 Web 处理）。现有“待确认余额”散落在设置页与登录页（`SettingsView.swift:41-53`、`LoginView.swift:85-98`）的问题因此消失。
- **筛选条件也是对象**：日志筛选的“账号/用户/分组/Key”是 `EntityRef` 令牌，选择它们用的就是全局搜索组件（同一组件三处复用：全局搜索、对象选择器、日志筛选），手输数字 ID 的表单字段全部删除（修 `01 D14`、`03 A12`）。
- **统计分析是“对象上的视图”**：站点级、账号级、分组级、用户级分析是同一页面 `AnalyticsView(scope:)`，排行榜里的每一行（模型、分组、用户）又是链接。
- **对象缓存是单一事实来源**：`EntityStore` 以 `EntityRef` 为键缓存快照；任何写操作成功后更新缓存，所有正在显示该对象的行、徽章、头部同步刷新（停用调度后返回列表，行已经是“暂停”）。

| **R5** IA 碎片化 | 日志埋在“管理”、分析 4 个入口、切站只在设置、手输 ID、无跨实体搜索（`01 R7`） | 单一 `Route`；全局搜索；关系芯片；对象令牌筛选；Tab 由角色 + 开关推导；目录有收纳规则（§2.6） | 入口不再是“页面”，而是“对象”；同一对象从任何地方进入都是同一页，入口重复在结构上不可能发生 |
| **R6** 操作语义失当 | 10 个确认全 destructive、3 种提交范式、成功写成常驻分区、sheet 叠 sheet、无触觉（`05 §2#6`、`03 A10`） | 动作注册表定义级别、动词、位置；`ActionHost` 统一四级确认、单 sheet、内嵌 step-up；`FeedbackCenter` 统一 toast / 撤销 / 待核对横幅 / 触觉 | 页面不再自己写确认和提交；级别由动作定义决定，“启用调度弹红色确认”这种错误无处可写 |

### 1.4 对象中心的风险与“救火足够快”的保证

对象中心天然的风险是**层级变深**：“先找到对象，再在对象页操作”。本方案用五个机制抵消：

1. **收件箱即对象**：概览首屏第一块是“需要关注”，每条都是一个对象或对象集合；单对象条目可直接滑动处置（如“清除限流”），不必进入对象页。
2. **问题条前置**：对象页首屏第一个可交互元素就是恢复动作（“限流中 · 12:41 恢复 [清除限流]”）。
3. **动作随对象走**：任何地方出现的账号行都有同一组滑动与长按动作（§5.1）。
4. **快照首帧**：行把快照带进对象页，首帧即有名称与状态，详细数据随后到达，没有“白屏骨架”。
5. **搜索直达**：请求 ID、邮箱、账号名两步到对象（§3）。

```swift
// Sub2Core 拟新增：唯一导航值
public struct EntityRef: Hashable, Codable, Sendable {
    public let kind: EntityKind
    public let id: String                 // Int 或 request_id，统一字符串化
    public var snapshot: EntitySnapshot?  // 名称、主状态码、副标题、更新时间；不参与 Hashable
}
public enum Route: Hashable, Codable, Sendable {
    case entity(EntityRef)
    case collection(EntityKind, CollectionQuery)   // 带预置筛选的对象集合
    case records(RecordQuery)                      // 失败请求 / 上游错误 / 用量明细 + 对象令牌
    case analytics(AnalyticsScope)                 // 站点 / 账号 / 分组 / 用户
    case module(ModuleID)                          // 目录里的低频模块根页
}
```

### 2.2 关系：哪些是“芯片”，哪些是“关系行”

- **反向（对多）关系 → 页尾“关系”区的 `RelationRow`**：带计数，点击 push 预置筛选的集合或记录页。

### 2.4 Tab 由“角色 + 站点功能开关”推导

| 角色 | Tab 集合（按顺序） | 首页定位 | 目录（浏览） | 依据 |
|---|---|---|---|---|
| **admin（本轮）** | 概览 · 账号 · 用户 · 监控* · 搜索 | 概览收件箱 | 分组、请求记录、统计分析；近期：代理、订阅*、兑换码、公告；后期：订单*、风控日志*、操作审计 | `02 §6.2` |
| **vendor（以后）** | 账号† · 分组† · 记录 · 搜索 | 账号 Tab 的“需处理”范围即首页（vendor 无 `dashboard/stats`，`02 §1.6`） | 代理†、趋势（仅 `dashboard/trend/models/groups`） | `02 §1.6`；`05 §4.1` 权限档 `account_manage / group_ops / group_billing / proxy_manage / monitor_view` |
| **普通用户（以后）** | 首页 · 密钥 · 记录 · 状态*；**不设搜索 Tab**（对象少，记录页内 `.searchable` 支持请求 ID） | 首页：余额、今日用量、订阅进度、异常 Key | 兑换、订单、邀请返利、模型广场（Web 跳转为主） | `02 §2`、`02 §6.2C` |

`*` 由站点开关决定；`†` 由 vendor 权限档决定；“记录”对 vendor/用户是一级 Tab（他们没有“用户”“概览”，日志成为最高频对象集合），对 admin 不是。

**推导规则**

1. **只在会话建立时计算**。切换站点 = 新会话：根视图以 `.id(sessionGeneration)` 重建（复用现有代际守卫，`AppModel.swift:24`），若新集合里存在同名 Tab 则保持选中。
2. **会话中途开关变化不移除 Tab**：例如站长在 Web 关闭渠道监控，本会话内该 Tab 显示 `FeatureOffState`，下次会话推导时才消失（HIG：不要动态隐藏 Tab，`03 §1.1`）。
3. **不摆空壳**：推导结果里没有的模块，在目录、搜索范围、关系行、收件箱规则里都同步消失；不出现“即将推出”“仅 Web 可用”的灰色入口（Web-only 模块统一在“在 Web 中管理”分组里，以外链形式出现）。
4. **未知即关闭**：开关读不到时按“未开启”处理；若用户经深链或置顶进入，显示 `FeatureOffState`。
5. **403 兜底**：任何接口返回 403 显示 `PermissionState`，并在本地记住，使下次会话推导时裁掉该模块。
6. **数据来源**：角色来自登录响应 `user.role`（现有 `AdminUser.role`，`Models.swift:88`）；站点开关来自 `GET settings/public`（登录时已请求，`APIClient.swift:38`，需扩展解码，键名以 Web `AppSidebar.vue:766-787` 读取的同名公开设置为准【待验证】）；ops 开关见 `02 §1.6`（`ops_monitoring_enabled`）；vendor 权限档来自 `GET admin/workspaces/me`（`02 §1.2`）。

### 2.5 站点切换放在哪里

- **每个 Tab 根页的前置工具栏位放“站点徽记”**（`ToolbarItem(placement: .topBarLeading)`）：站点 Logo（来自 `settings/public` 的 `site_logo`，`05 §4.12`）或首字母徽记，外圈为按站点 ID 派生的固定色环。点击弹出 `Menu`：站点列表（当前站点带对勾与登录身份）、“添加站点…”、“站点与设置…”。
- **根页导航副标题常驻站点名**：`.navigationSubtitle("主站")`（iOS 26）。
- **写操作复核处必现站点徽记**：所有二级以上确认、复核页、批量结果的标题区都带站点徽记与名称（替代现在在 message 里写“站点：xxx / 地址：URL”，`01 C29/C74`）。
- 切站本身是只读动作，不确认；但若存在**进行中的提交**或**打开中的有改动的表单**，菜单项禁用并显示原因“有未完成的操作”。切换成功后 `.sensoryFeedback(.selection)` + toast“已切换到 备用站”。

不采用：大标题上方自绘站点栏（`05 §5.2` 指出与系统导航栏冲突、占首屏）。

### 2.6 低频模块：放在哪、收纳规则、哪些保持 Web

**放置**：搜索 Tab 的空状态（iPhone）/ iPad 侧栏的 `TabSection("浏览")`（§10）。概览底部只保留一个“统计分析 ›”行（早晚看数据的自然延伸）。

**收纳规则（硬规则，写进 `NavigationPlan` 的单元测试）**

1. **只收“对象类型”或“对象视图”**，不收功能杂项；每个条目打开一个对象集合或一个带作用域的视图。
2. **已是 Tab 的对象不进目录**（账号、用户、监控不重复出现，避免 `05 §5.3` 指出的 A 原型重复项）。
3. **最多三组**：「对象」「记录」「运营」，每组 ≤6 项；超出的一律归入“在 Web 中管理”。
4. **按角色与开关裁剪**，与 Tab 同一推导函数产出。
5. **每个模块明确归类为“原生”或“Web”**；Web 模块只以外链（`openURL` 打开站点对应路径）出现在“在 Web 中管理”组，标 `↗`。
6. **进入目录的门槛**：该模块在手机上至少有一个“看 + 一键处置”的场景（`02 §0.3` 的“偶尔”或“高频”）；纯配置不进原生目录。

#### 4.0.3 行解剖通则 `ObjectRow`

```
│ [符号] 主标题（headline，单行尾截断）        右上：倒计时/相对时间/金额（等宽）
```

### 5.1 手势与入口分配（动作随对象走）

| 手势 | 规则 | 账号行 | 用户行 | 失败请求/上游错误行 | 告警/探测行 |

| 点按 | 永远 = 打开对象页（选择模式下 = 勾选） | 对象页 | 对象页 | 对象页 | 对象页 |

### 5.2 确认分级（四级）

| 级别 | 适用 | UI | 按钮文案 | 反馈 |
|---|---|---|---|---|
| **一级 · 轻触即做** | 单对象、可逆或自愈：启用/停止调度、清除限流、恢复状态、解除临时不可调度、标记已处理、确认告警、立即运行探测、启用用户；表单内“保存” | 无弹窗；按钮内进度；成功 toast，**可逆者带“撤销”5 秒** | 动词即结果：“停止调度” | `.success` / `.error` |
| **二级 · 普通确认** | 可逆批量；单对象但影响面大且可逆：禁用用户、停用分组、刷新凭据、重置配额、静默告警 | `confirmationDialog` **挂在触发按钮上**（iOS 26 从按钮处弹出，`03 §1.8`）；标题含数量与对象；确认按钮**非 destructive** | “停止 5 个账号的调度”“禁用 alice@…” | 同上；批量为逐项结果 |
| **三级 · 破坏性确认** | 资金（充值/退款/校正余额）、删除（分组）、移除站点与凭据、退出登录、标记待核对已在 Web 处理 | 资金：sheet 内**复核步骤**，主按钮 `role: .destructive` 写明金额与对象；删除/退出：`confirmationDialog` destructive，写明对象与后果 | “确认充值 $50.00”“删除分组「标准分组」” | 成功 `.success`；不明 `.warning` + 待核对 |
| **四级 · 二次验证** | 服务器要求 step-up 的操作（创建/提升管理员；以后的导出等，`02 §1.6`） | 在当前 sheet 内 push `StepUpStep`（6 位验证码）；验证后回到复核/表单，用户需再次确认（保留现有语义） | “验证” | 验证失败原位提示 |

确认中的站点标识：二级以上的标题区都带站点徽记；message 不再列 URL、完整 ID、全部对象名（最多 3 个名称 + “等 N 个”）。

### 5.3 反馈：成功 / 失败 / 待核对

| 结果 | 呈现 | 持续 | 触觉（`sensoryFeedback`，iOS 17） |
|---|---|---|---|
| 成功（一级/二级） | 底部浮动 `Toast`（玻璃，在 Tab 栏上方），一句“已停止 gpt-pool-07 的调度”+ 可选“撤销” | 4–5 秒，可滑走 | `.success` |

### 5.4 撤销

- 只对**存在逆操作**的一级动作提供：启用/停止调度（单个）→ 逆调用；批量调度 → 结果页“撤销本次操作”（二级）；标记已处理 → 仅当接口支持 `resolved=false`【待验证】。
- 撤销本身也走写入协调器（结果不明时不再提供撤销，转待核对）。
- 恢复类动作（清除限流、恢复状态）没有逆操作，不提供撤销；其“可逆性”来自后端会在再次出错时重新标记，属于自愈。

### 5.5 未保存草稿保护

- 有改动的表单：`.interactiveDismissDisabled(isDirty)`；“取消”→ `confirmationDialog`“放弃修改？”。【推断】可在第二阶段用 `UIAdaptivePresentationControllerDelegate.presentationControllerDidAttemptToDismiss` 桥接，让下滑也弹同一对话框（HIG Sheets 建议）。
- 非资金表单的草稿以 `EntityRef` 为键保存在内存 `DraftStore`（不落盘）；意外关闭后重新打开同一对象的编辑，提示“恢复上次未保存的修改？”。
- 资金表单的金额**不保存草稿**；一旦发送，由现有未决持久化接管。
- 切站、退出、进入后台超过 10 分钟时清空草稿。

### 5.6 Sheet 规则

1. **全局同一时刻最多一张 sheet**（HIG，`03 §1.6`）。sheet 只由 `ActionHost`（每个 Tab 根挂一个 `.sheet(item: $host.presentation)`）呈现。
2. 需要新步骤（对象选择、二次验证、人机验证、复核、结果）时，在当前 sheet 的 `NavigationStack` 内 **push**，绝不再 present。
3. sheet 内需要跳到别的对象页（如测试失败后“查看此账号错误”）：先关闭 sheet，再在底层栈 push。
4. `confirmationDialog` 不是 sheet，可以出现在 sheet 之上；alert 仅限阻断事件。
5. detent：筛选、测试、批量结果 `[.medium, .large]`；编辑、资金 `.large`；不设置 `presentationBackground`（`03 §1.6`）。

### 5.7 返回栈与跨对象跳转

1. **关系跳转一律在当前 Tab 的栈内 push**，不隐式切换 Tab（修 `05 §5.6` 原型倒退）。从概览收件箱点“3 个账号限流中”也是在概览栈内 push 账号集合，返回即回到收件箱。
2. **去重回退**：目标 `Route` 已在当前栈中时，pop 回该位置而不是再 push，从结构上消除“分组 → 账号 → 日志 → 账号 → 日志……”的无限环（`01 §1`）。
3. **原地替换**：在记录页里“按此账号筛选”、在集合页里改筛选，修改的是栈顶 Route 的查询，不新增层级。
4. **再点当前 Tab**：回到根；在根再点：滚到顶部（搜索 Tab：聚焦搜索框）。【待验证】系统是否已默认实现，未实现则经 `TabView(selection:)` 的重复选择检测清空 path。
5. **深链**（以后：通知、小组件、Spotlight、URL `sub2://<站点>/<kind>/<id>`）：切到该 kind 所属 Tab（账号→账号，用户→用户，记录/分组→搜索），栈重置为 `[对象]`；站点不同时先确认切站。
6. **长按返回按钮**显示历史栈（系统行为），作为深栈的“面包屑”。
7. 切站、退出：所有栈清空。

### 5.8 刷新

- 每页只有下拉刷新一个手动入口；分区不再有“刷新××”按钮。
- 前台自动刷新：概览、账号集合 30 秒，监控 60 秒；后台、页面不可见、选择模式、sheet 打开时暂停（沿用 `DashboardView.swift:294-295, 420-444` 的机制）。
- 新鲜度只在**过期**时出现：超过 2 个刷新周期未成功 → `StaleBanner`“显示 10:02 的数据 · 刷新失败 · 重试”。

### 5.9 文案规则（结构层面）

- 动作用业务动词：启用调度 / 停止调度、充值 / 退款、恢复状态、清除限流、标记已处理；状态用词典词：正常 / 停用 / 错误 / 暂停 / 限流中……（`00 §2`、`04 §4.1`）。
- 不出现：接口、快照、自动重试/重放、幂等、精确匹配、独立加载、“确认发送/执行/操作”、原始英文枚举、`#ID` 作为对象名。
- 缺失值：“—”；需要解释时在详情里写一次“站点未提供此数据”。

## 7. 账号状态模型

### 7.1 四个维度

| 维度 | 字段（`02 §3.1`） | 取值 → 词 / 色 / 符号 | 恢复动作 |
|---|---|---|---|
| **管理状态** | `status` | `active` 正常·绿·`checkmark.circle.fill`；`inactive`/`disabled` 停用·灰·`minus.circle.fill`；`error` 错误·红·`xmark.octagon.fill` + `error_message` | 恢复状态 `POST :id/recover-state`；清除错误 `POST :id/clear-error` |
| **调度开关** | `schedulable` | true 参与（不显示）；false 暂停·灰·`pause.circle.fill` | 启用调度 / 停止调度 `POST :id/schedulable`（已接入） |
| **限时运行状态** | `rate_limit_reset_at`（+`rate_limited_at`） | 限流中·琥珀·`hourglass` + 倒计时 | 清除限流 `POST :id/clear-rate-limit` |
| | `overload_until` | 过载中·红·`flame.fill` + 倒计时 | 恢复状态 `POST :id/recover-state` |
| | `temp_unschedulable_until` + `temp_unschedulable_reason`（JSON：状态码、命中关键词、触发次数……） | 临时不可调度·琥珀·`clock.badge.exclamationmark` + 恢复时刻 + 原因摘要 | 解除 `DELETE :id/temp-unschedulable`；详情 `GET :id/temp-unschedulable` |
| | `extra.model_rate_limits`（按模型；键 `AICredits` 表示积分耗尽） | 模型限流 N·紫·`cpu`；积分耗尽·红 | —（随时间恢复） |
| | `quota_*_used ≥ quota_*_limit` | 配额超限·琥珀·`gauge.with.dots.needle.100percent` | 重置配额 `POST :id/reset-quota`（二级） |
| | `session_window_status`（已解码） | `allowed_warning` 会话接近上限·琥珀；`rejected` 会话已满·红 | — |
| **有效期** | `expires_at`（已解码）+ `auto_pause_on_expired` | ≤7 天“3 天后过期”·琥珀；已过期·灰·`calendar.badge.exclamationmark`（自动暂停时附“已自动暂停”） | 在 Web 中续期 ↗ |
| 附加 | `proxy_fallback_origin_*` | 代理已回退·琥珀·`arrow.triangle.branch` | 撤销回退 `POST :id/revert-proxy-fallback`（P2） |

### 7.2 派生规则

```swift
// Sub2Core 拟新增；与 Web AccountStatusIndicator 的判定顺序一致（04 §4.1#6），单测对照 Web 用例
public struct AccountCondition: Sendable {
    public let admin: AdminState            // normal / inactive / error(message)
    public let paused: Bool                 // !schedulable
    public let blocks: [TimedBlock]         // rateLimited(until) / overloaded(until) / tempUnschedulable(until, reason)
                                            // modelLimited([model: until]) / quotaExceeded(dims) / sessionWindow(level)
    public let expiry: Expiry               // none / soon(date) / expired(date, autoPaused)
    public var primary: AccountBadge        // 见下方优先级
    public var secondary: [AccountBadge]    // 最多 2 个，其余 "+N"
    public var needsAttention: Bool         // 错误 ∪ 限流 ∪ 过载 ∪ 临时 ∪ 配额超限 ∪ 会话已满
    public var nextRecovery: Date?          // 所有限时状态中最早的恢复时刻
    public static func derive(_ account: UpstreamAccount, now: Date) -> AccountCondition
}
```

**主徽章优先级**：限流中 > 过载中 > 错误 > 临时不可调度 > 停用 / 已过期 > 配额超限 > 暂停 > 正常。
**附加标签**：主徽章之外仍成立的状态，按同一优先级取前 2 个（如“限流中”为主时，“暂停”“模型限流 2”为附加）；“即将过期”“代理已回退”只作附加。
**到期即失效**：时间已过的限时状态不再显示为限流，而显示“已到恢复时间”并触发该账号单独刷新（`EntityStore.refresh(ref)`）。

### 7.3 倒计时、恢复动作与动作表

- **倒计时显示**：剩余 <1 小时用 `Text(timerInterval: now...until, countsDown: true)`（iOS 16，系统自动刷新，无需 Timer）；≥1 小时显示恢复时刻“14:30 恢复”；跨日显示“明天 09:00 恢复”。VoiceOver 读“限流中，还剩 8 分钟，12 点 41 分自动恢复”。
- **恢复动作**都是一级（自愈、低风险），成功后立即重新读取该账号（`GET :id`），以服务器状态为准更新徽章；若服务器仍返回限流，toast 改为“已提交，账号仍处于限流”。

| 动作 | 出现条件 | 级别 | 接口 | 位置 |
|---|---|---|---|---|
| 停止调度 / 启用调度 | 总是（按 `schedulable`） | 一级 + 撤销；批量二级 | `POST :id/schedulable`；`bulk-update` | 行右滑、长按、主操作、批量条 |
| 清除限流 | 限流中 | 一级 | `POST :id/clear-rate-limit` | 问题条、行左滑、长按、批量“更多” |
| 恢复状态 | 错误 / 过载中 | 一级 | `POST :id/recover-state` | 同上 |
| 解除临时不可调度 | 临时不可调度 | 一级 | `DELETE :id/temp-unschedulable` | 同上 |
| 清除错误 | 错误 | 一级 | `POST :id/clear-error` | ⋯ 菜单 |
| 重置配额 | 配额超限 | 二级 | `POST :id/reset-quota` | 问题条、⋯ |
| 测试… | 总是 | 测试面板 | `POST :id/test`（SSE，已接入） | 主操作、长按 |
| 刷新凭据… | `type ∈ oauth / setup-token` | 二级；批量二级 | `POST :id/refresh`（已接入） | ⋯、批量“更多” |
| 编辑… | 总是（vendor 视权限） | 表单 | `PUT :id`（已接入） | 主操作、长按 |
| 查看错误 / 请求 / 统计 | 总是 | 导航 | — | 问题条、关系、长按 |
| 置顶 / 复制名称 / 复制编号 | 总是 | 本地 | — | 导航栏、长按 |
| 在 Web 中编辑凭据与代理 | 总是 | 外链 | — | ⋯ |

### 7.4 在行、详情、筛选、收件箱中的呈现

| 位置 | 呈现 |
|---|---|
| **列表行** | 第二行：主徽章（词 + 符号 + 色）+ 恢复时刻；附加标签最多 2 个；错误时附脱敏原文一行；右上角为最近恢复的倒计时 |
| **对象页摘要头** | 主徽章 + 倒计时 + 附加标签；问题条展示最高优先级问题与首选恢复动作 |
| **对象页“状态”分段** | 四维逐行：管理状态 / 调度 / 每个限时状态（一行一个，各带恢复动作）/ 有效期；临时不可调度展开原因（状态码、命中关键词、触发次数） |
| **筛选** | 范围分段“需处理 / 全部”；状态筛选项与 Web 一一对应：全部状态、正常、停用、错误、限流中、临时不可调度、不可调度（`04 §4.1#8`，服务器值 `active / inactive / error / rate_limited / temp_unschedulable / unschedulable`） |
| **收件箱** | 单个：“gpt-pool-07 限流中 · 08:12”；多个：“3 个账号限流中 · 最早 12:41 恢复 · 按平台计数” |
| **搜索结果 / 关联行** | 同列表行（同一 `ObjectRow`） |
| **VoiceOver** | 行 label：“gpt-pool-07，限流中，12 点 41 分恢复，已暂停调度”；自定义动作：清除限流、启用调度、测试 |

**前提【待验证】**：账号列表使用 `lite=true`（`AccountManagement.swift:30`）；需核对 lite 模式是否返回上述限时字段。若不返回，“需处理”三个分区改为非 lite 请求（每区首页 20 条，代价可控）。

## 10. iPad：本轮“能用”，后期认真适配

**本轮（不额外设计专属页面）**

- `TabView` 用 `.tabViewStyle(.sidebarAdaptable)`：iPad 横屏为侧栏，竖屏/分屏可切回顶部 Tab 栏。
- **目录进侧栏**：`TabSection("浏览") { Tab("分组"…); Tab("请求记录"…); Tab("统计分析"…) }`，在 iPhone 上用 `.defaultVisibility(.hidden, for: .tabBar)`（iOS 18）隐藏，只在侧栏出现——同一份 `NavigationPlan.catalog` 在 iPhone 是搜索页的“浏览”，在 iPad 是侧栏分组，零额外入口逻辑。
- **集合 → 对象双栏**：`AdaptiveCollectionContainer` 在 `horizontalSizeClass == .regular` 时用 `NavigationSplitView { EntityCollectionView(selection:) } detail: { NavigationStack(path:) { EntityPageScaffold } }`，compact 时退化为单个 `NavigationStack`。路由不变（`Route` 只是从“push”变为“设为 detail 根 + push”）。
- 对象页最大可读宽度 `frame(maxWidth: 720)` 居中；`PropertyGrid` 在宽屏自动 4 列。
- sheet 在 iPad 用 `.presentationSizing(.form)`（iOS 18）。
- 验收：iPad 模拟器横竖屏、分屏 1/3 宽各走一遍救火链与充值链。

**后期深度适配预留**

| 能力 | 预留点 |
|---|---|
| 多列表格（日志、账号） | `EntityRowModel` 已是结构化数据，可直接喂给 `Table`（iOS 16）列 |
| 检查器 | 请求/错误详情在 regular 宽度改为 `.inspector(isPresented:)`（iOS 17），列表不离开 |
| 多窗口 | `EntityRef` 遵循 `Codable` + `Transferable`，可 `openWindow(value: ref)` 在新窗口打开对象；`@SceneStorage` 保存编码后的 path |
| 拖放 | 把账号行拖进记录页筛选条即添加对象令牌（`.draggable(ref)` / `.dropDestination(for: EntityRef.self)`） |
| 键盘 | `⌘F` 聚焦全局搜索、`⌘R` 刷新、`⌘⌫` 停止调度等 `.keyboardShortcut` |
| 指针 | 行 `.hoverEffect(.highlight)`；芯片悬停预览 |

| 契约迁到测试 | 每条验收契约（如“缺失 RPM 不以配置限额代替”“缺失实际费用不以标准费用代替”）改写为 Core 展示层断言：`AccountMetric.currentRPM(nil) == .missing`；`docs/ACCEPTANCE.md` 每条注明对应测试位置 |
| 文案 lint | `CopyLintTests` 扫描 `NativeApp/**/*.swift` 字符串字面量，禁用：接口、快照、自动重试、自动重放、幂等、精确匹配、独立加载、前台每、未以、不以、确认发送、确认执行、确认操作、IPA、`#\(`（以编号当名称）；“不可用”只允许出现在 `StatusDictionary`（渠道状态词）；“Web 后台”只允许出现在 `WebLink` 组件 |
| UITest 不看文案 | 见 §12.4；测试没有理由要求屏幕上“写出”某句话 |
| 评审清单 | PR 模板增加一项：“新增的界面文字是否在说业务？是否能被状态/组件替代？” |

### 12.6 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| `lite` 列表不返回限时字段 | 行内看不到倒计时 | 需处理分区改非 lite；全部范围只显示主状态，倒计时在对象页 |
| 搜索扇出在大站点慢（`users?search` 模糊查询） | 搜索卡顿 | 每类独立加载、取消旧请求、每类只取 5 条、意图识别减少扇出 |

| 功能开关键名未知 | Tab 推导错误 | “未知即关闭”+ 403/404 记忆修正；阶段 0 对照 Web 源码定稿 |
| iOS 27.2 搜索 Tab 行为差异 | 搜索 Tab 退化为内联 | `.tabViewSearchActivation(.searchTabSelection)`；Mac 上两种挂法实测 |
| 对象中心层级变深 | 救火变慢 | 收件箱滑动处置、问题条、动作随对象走、快照首帧（§1.4）；以 §3 步数为验收 |
| 栈过深迷失 | 用户不知道在哪 | 去重回退、长按返回看历史、对象页标题带 kind 图标 |
| 过载账号无筛选值、告警无账号维度 | “需处理”不完整 | 过载只计数并说明落点；告警落到分组的需处理账号（§2.2） |
| API Key 无单取接口 | Key 对象页无法深链刷新 | Key 页只从父列表快照构建，深链落到所属用户页 |
| 最近/置顶含个人信息 | 隐私 | 文件保护、按身份隔离、退出清除 |
| UITest 重写工期 | 回归保护空窗 | 按阶段替换、阶段末归零；Core 测试先行承接契约 |
| 统一 `List` 内嵌在 `ScrollView`（收件箱滑动）手感 | 嵌套滚动冲突 | 原型期比较“嵌入 List”与 iOS 27 `swipeActionsContainer()`，择优 |
