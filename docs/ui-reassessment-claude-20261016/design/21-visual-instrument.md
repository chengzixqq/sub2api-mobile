## 0. 一页摘要

- **名称**：游标（Vernier）。游标卡尺上那根副尺，作用是把读数精确到最后一位。
- **一句话**：每个数字都当作仪表读数来排：石墨面板、发丝刻度，只用一种信号青。平时不亮灯，只有需要管理员动手时才亮。
- **五条法则**
  1. **暗座舱**：正常状态不着色，颜色只用来标出例外。
  2. **读数优先**：数字是版面主角，全部用等宽数字，单位比数字小一级、颜色淡一级。
  3. **刻度即结构**：用发丝线、刻度切口和对齐组织信息，不用阴影和卡片堆叠。
  4. **信号青只代表“可操作 / 已选中”**，不表示任何状态。
  5. **六种颜色只说六件事**：绿、琥珀、红、灰、紫各对应一种语义，橙只表示成本，不再挪作他用。
- **可识别特征**（第 1.5 节）：状态脊、近直角灯牌、带刻度切口的游标条、窄体读数、刻度线标头、固定读数窗、成本三口径用线型区分、1 物理像素的发丝线。
- **对比度**：浅色、深色、增强对比度共 4 套外观，逐对计算 188 组（其中 4 组是不设门槛的装饰性发丝线），其余全部达标（文字 ≥4.5:1，图形 ≥3:1），详见第 2.6 节。琥珀和红色的色值专门为色弱用户调过（第 2.8 节）。
- **Liquid Glass**：外壳全部交给系统。自定义 `.glassEffect` 只有两处：批量选择坞、操作回执胶囊。

## 1. 名称、概念与定位

### 1.1 名称与概念

**游标 · Vernier**：把管理端做成一台校准过的仪器，而不是一份报表或一个仪表盘模板。

种子方向是“精密仪器 / 驾驶舱”。本方案在此基础上补了三个具体来源，让“精密”能落到规则上：

| 来源 | 借用什么 | 落到本方案 |
|---|---|---|
| 民航“暗座舱 / Lights out”理念（Airbus 自 A310 起采用）：系统正常时顶板按钮不亮灯，故障或开关处于非常规位置时才亮。琥珀=故障，红=需立即处置，绿=正常运行（[Aeropeep](https://aeropeep.com/which-aircraft-uses-the-dark-cockpit-concept/)、[Avia Pro](https://aviaproconsulting.com/article/post/engineering-spotlight-the-ergonomics-of-annunciation-%E2%80%93-airbus-lights-out-vs-boeing-quiet-and-dark)） | 色彩只给例外 | 正常账号只有一个 6pt 绿点；异常账号才有状态脊、灯牌和倒计时 |
| FAA AC 25-11A/B 驾驶舱显示配色：红只用于警告、琥珀只用于告诫，不得挪作他用；“如果用颜色编码，至少再配一种编码（尺寸、形状、位置）”；青用于“已选数据 / 预位”（[FAA AC 25-11B](https://www.faa.gov/documentLibrary/media/Advisory_Circular/AC_25-11B.pdf)、[AC 25-11A 色表](https://www.faa.gov/documentLibrary/media/Advisory_Circular/AC_25-11A.pdf)） | 颜色专用、冗余编码、青=可选 | 语义色专用化；状态永远是“图形 + 文字 + 颜色”；信号青只表示可操作和选中 |
| 瑞士国际主义排版、Linear 的克制（2024 年改版改用 LCH 生成主题，界面几乎全是无彩色加一个强调色，[Linear](https://linear.app/now/how-we-redesigned-the-linear-ui)）、Teenage Engineering 的“颜色是配给的”（品牌外观几乎单色，颜色只用于状态和对应关系，[分析](https://www.unknownarts.co/p/teenage-engineering-op-1-the-micro)） | 网格、发丝线、无阴影、少量颜色 | 刻度线标头、模块化面板、窄体读数 |

### 1.2 为什么适合“中文优先的 AI API 中转站运营工具”

| 任务（简报 §1） | 本方向如何服务 |
|---|---|
| **救火**：看账号异常和限流 | 正常行没有颜色，异常行自带左侧 3pt 状态脊和灯牌，一眼向下扫过左缘就能定位。限流倒计时用窄体大号读数（`04:12`），回答“什么时候恢复”这个最关键的问题 |
| **账务**：加余额、退款、早晚看营收 | 金额全部用等宽数字，小数点上下对齐；成本三口径用**线型**区分（实线、虚线、点线），金额文字本身不着色，避免“红涨绿跌”的误读 |
| **监控**：渠道、健康分 | 游标条和刻度尺直接画出“离阈值还有多远”，阈值与 Web 一致（容量 75/90，健康分 60/90） |
| **中文优先** | 苹方是结构均匀的无衬线体，与 SF Pro 的理性气质一致，瑞士网格对方块字天然友好。本方向不混用衬线和圆体，避免中西文风格割裂（第 3.2 节）。颜色用量少，也绕开了中文语境里红绿方向相反的问题（HIG Color 以股票 App 为例：中文环境下涨为红） |
| **信任** | 克制的外观本身就是可靠性信号：没有装饰性渐变和发光，每个像素都在传递数据。缺失值统一显示为“—”，绝不用 0 或标准费用冒充（沿用 Sub2Core 的数据真实性原则） |

### 1.3 与另外两种风格的根本区别

三种风格对应三种不同的“信息载体”，不是同一套界面换配色：

| 维度 | **游标（精密仪器，本方案）** | 账簿编辑 | 夜航信号 |
|---|---|---|---|
| 信息的主要载体 | **刻度与读数**：位置、比例、对齐 | 版式与文字：标题层级、栏线、叙述 | 光：亮度与饱和色 |
| 颜色立场 | 暗座舱：正常不发光，颜色只标例外 | 墨色为主，会计式红黑 | 颜色就是信号：深底上多色发光 |
| 字体 | SF Pro + 等宽数字 + 窄体读数；不用衬线和圆体 | New York 衬线标题 + SF 正文 | SF Pro Rounded 或 Mono，高对比 |
| 表面 | 石墨面板模块、发丝线、无阴影 | 暖白纸面、账页横线 | 近黑底、发光描边 |
| 深浅色 | 两套同等地位 | 以浅色为主 | 以深色为主 |
| 最擅长 | 几秒内扫读、判断容量、救火 | 对账、读日报 | 夜间值守 |
| 主要风险 | 偏冷、工程感 | 密度低；衬线西文与无衬线中文混排 | 白天可读性差、容易视觉疲劳 |

### 1.4 拒绝的模板

- iOS 设置页式的 insetGrouped 卡片堆叠（根因 R1）：列表改为满宽 plain 行加发丝分隔。
- 胶囊徽章：改为圆角 3pt 的近直角“灯牌”，像仪表铭牌。
- 系统灰加一个强调色：中性色带轻微冷调（色相约 200°），文字分三级明度阶，信号青只在可操作处出现。
- 柱状图用渐变紫：图表数据一律用石墨色，选中时用信号青，阈值用语义色虚线。
- 阴影：内容层没有任何阴影，层级只靠明度台阶和发丝线表达。

### 1.5 可识别特征清单（品牌个性来自这些，不靠装饰）

1. **状态脊**：异常行最左侧 3pt 竖条，颜色对应语义（`.listRowBackground` 实现）。
2. **灯牌**：圆角 3pt 的状态铭牌，“图形 + 文字”，底色是对应语义色的淡色。
3. **游标条**：容量 / 配额条，轨道上在 25/50/75% 处有 1pt 刻度切口；超过 100% 时右端出现 2pt 红色“越限帽”。
4. **窄体读数**：title2 及以上的数字使用 SF Pro Condensed + 等宽数字，像仪表上的数码读数。
5. **刻度线标头**：分区标题后接一条延伸到右缘的发丝线，右端放元信息（如“00:00 起”）。
6. **固定读数窗**：图表选中值显示在图表标题行的固定位置，不弹浮层。
7. **线型编码**：成本三口径为 实际=实线、成本=虚线、标准=点线。
8. **1 物理像素发丝线**：线宽 `1 / displayScale`，3x 屏上为 0.33pt。
9. **信号青**：全 App 唯一的品牌色，只出现在可操作、已选中、读数游标处。
10. **暗座舱的“全部正常”行**：没有待处理事项时，首页只显示一行静默确认，不放庆祝插画。

## 2. 色彩

### 2.1 色彩法则

1. **双令牌**：每种语义色分为 `ink`（文字和图标，≥4.5:1）、`lamp`（填充、状态脊、图表标记，≥3:1）、`wash`（灯牌底色，是 lamp 按浅色 12% / 深色 18% 叠在 panel 上的实色）。
2. **语义色专用化**（含义与简报 §2 一致，色值按本风格调校）：

   | 语义 | 色调令牌 | 含义（与 Web 一致） | 本方向的额外约束 |
   |---|---|---|---|
   | 绿 | `normal` | 正常 / 可用 / 健康 | 列表里只出现 6pt 圆点，不用绿色文字 |
   | 琥珀 | `caution` | 限流中、临时不可调度、配额超限、接近上限（≥75%）、性能下降 | 一律配倒计时或比例 |
   | 红 | `fault` | 错误、过载中、不可用、≥90% | 唯一允许出现在首页第一屏的强色 |
   | 灰 | `idle` | 停用、暂停、未知、无样本 | 名称同时降为 `ink2`，表示退出轮转 |
   | 紫 | `model` | 模型级限流 | 只作附加标签，不当主状态 |
   | 实际 / 成本 / 标准 | `Ledger` | 绿 / 橙 / 灰 | 只用于图例刻度和图表系列；金额文字保持 `ink1` |
   | 青 | `signal` | **不是状态**：可操作、已选中、读数游标 | 不得用于任何状态 |

3. **Web 中的其他着色在本方向一律去色**，避免挤占上面的语义：平台品牌色（OpenAI 绿、Anthropic 橙……）、错误类型六色、请求类型五色、Token 构成四色。这些信息改用文字标签，分类图表改用石墨明度阶（第 7.2 节）。延迟分档中，Web 的“慢=橙”改为“琥珀 + ‘慢’字”，让橙色只表示成本。这是对 04 §4.1 第 13–16 行的有意调整：那些不是简报规定的状态语义。
4. **涨跌不着色**：环比只用 ▲▼ 和正负号，颜色保持 `ink2`。

### 2.8 色觉缺陷校验【已验证，模拟】

方法：Machado 2009 模型（严重度 1.0）模拟红色盲、绿色盲、蓝色盲，在 Lab 空间计算 CIEDE2000 色差，找出每种情况下最接近的语义色对。初版浅色方案的“琥珀 / 红”在绿色盲下 ΔE 只有 4.0，几乎无法区分。为此把琥珀灯调亮（`#B87D00`）、红灯压深（`#B42318`），拉开明度差：

| 浅色 · 最难区分的组合 | 正常视觉 ΔE | 红色盲 | 绿色盲 | 蓝色盲 |
|---|---|---|---|---|
| 琥珀 vs 红（调整后） | 32.7 | 22.5 | **15.4**（初版 4.0） | 18.4 |
| 琥珀 vs 成本橙 | 16.7 | 6.7 | **1.9** | 8.7 |
| 正常绿 vs 琥珀 | >27.5 | 7.2 | — | — |
| 正常绿 vs 信号青 | — | — | — | 6.1 |

| 深色 · 最难区分的组合 | 正常视觉 | 红色盲 | 绿色盲 | 蓝色盲 |
|---|---|---|---|---|
| 琥珀 vs 成本橙 | 19.5 | 12.4 | 8.4 | 11.7 |
| 正常绿 vs 红 | — | >19.8 | 9.7 | — |
| 正常绿 vs 信号青 | — | — | — | 8.9 |

结论与对策：
- **琥珀 vs 成本橙**在绿色盲下几乎相同。所以成本系列必须用虚线，琥珀阈值线是 `[3,3]` 短虚线，并带文字标注；两者不在同一视图里承担同类信息。
- **绿 vs 琥珀、绿 vs 青**在部分色弱下接近。但正常状态只用小圆点（形状区别于琥珀的沙漏图形），信号青不表示状态，所以不会造成误判。
- 所有状态都同时带 SF Symbol 形状和中文文字（第 6.2 节），满足 FAA 的“冗余编码”和 HIG 的 “Avoid relying solely on color”。

## 3. 字体

### 3.1 四种系统字体的角色

| 字体 | 角色 | 理由 |
|---|---|---|
| **SF Pro**（Text/Display 由系统按字号自动切换） | 全部界面文字与数字。数字一律等宽。title2 及以上的**纯数字读数**使用 Condensed 宽度（`Font.width(.condensed)`，iOS 16【已验证】） | 理性中性；窄体让 `$12,480.35` 能放进两栏网格，并带出“数码读数”的仪表气质 |
| **SF Mono** | 只用于**纯 ASCII 的技术标识**：请求 ID、Key 片段、HTTP 状态码、模型 ID（详情页）、账号测试的流式输出 | 等宽能逐字对齐便于核对；SF Mono 没有中文字形，中文会回退到比例宽度的苹方，导致对不齐，所以不用于中文 |
| **SF Pro Rounded** | **不使用** | 圆体传达亲和，与“精密”相冲突；苹方没有圆体，中西文会割裂。Tab 徽标等系统自绘部分由系统决定 |
| **New York** | **不使用** | 衬线是“账簿编辑”方向的标志。New York 没有中文字形，中文回退后会变成衬线西文配无衬线中文【推断：回退字体需真机核对】 |

### 3.2 苹方（PingFang SC）的实际表现与注意事项

1. **字重只有六档**：Ultralight、Thin、Light、Regular、Medium、Semibold，没有 Bold（[Apple 字体列表](https://support.apple.com/en-sg/103203)）。请求 `.bold`/`.heavy` 时中文大概率仍渲染为 Semibold【推断】，所以层级不能依赖 Bold 和 Semibold 的差别。本方向只用 Regular、Medium、Semibold 三档：Medium 用于行标题，Semibold 用于标头和灯牌。
2. **窄体不作用于中文**：苹方没有宽度轴。所以一个 `Text` 里不能混放窄体数字和中文。读数要拆成数字 `Text`（窄体）和中文单位 `Text`（标准宽度）两段，见 `Readout` 组件。
3. **等宽数字只作用于数字**：`monospacedDigit()` 对中文没有影响，混排安全。数字和拉丁字符由 SF Pro 渲染，汉字由苹方渲染，这是系统字体回退链的默认行为。
4. **行高**：根视图设置 `.typesettingLanguage(Locale.Language(identifier: "zh-Hans"))`（iOS 17【已验证】），让系统按中文调整行高和断行。即使设备语言是英文、内容是中文，也能得到正确的行距。
5. **字距**：不对中文额外设置 `tracking`，SF Pro 的动态字距由系统处理。
6. **中西文间距**：模板字符串里手动加半角空格，例如“近 24 小时”“限流 5”“并发 2/4”。
7. **标点与符号**：中文句内用全角标点；读数之间用“ · ”（U+00B7，两侧加空格）；时间范围用 en dash（`10/15 01:33–10/16 01:33`）；缺失值统一用 em dash “—”，并设置 `accessibilityLabel("未返回")`。
8. **截断**：ID、Key、邮箱用 `.truncationMode(.middle)`，同时保留开头和结尾；中文分组名用尾部截断。截断的内容都可以长按复制，或进入详情查看全文。

### 3.3 文字层级（全部基于 Text Style，自动跟随 Dynamic Type）

### 3.4 数字规则

1. **所有会对齐或会跳动的数字**（金额、计数、Token、延迟、百分比、HTTP 码、倒计时）一律 `monospacedDigit()`。
2. **窄体只用于 title2 及以上的纯数字读数**；更小的字号用标准宽度，保证可读性。
3. **单位比数字小一级、淡一级**：数值 `ink1`，单位 `ink3`，基线对齐（`HStack(alignment: .firstTextBaseline)`）。
4. **货币符号不与数字断开**：读数 `Text` 加 `.lineLimit(1)`，必要时用 `.fixedSize()`。
5. **金额文字不着色**，包括退款和扣减；方向用 U+2212 减号表示。

### 3.5 排版样例


### 3.6 Dynamic Type 策略

- 字号全部来自 Text Style，**不使用** `minimumScaleFactor`（03 A13）。
- 读数格四列 → 默认字号放不下时两列 → 辅助功能字号时一列（`ViewThatFits` 或 `AnyLayout`）。
- 列表行在 `isAccessibilitySize` 时隐藏元信息行（详情页提供全部信息），保留状态、名称和关键读数。
- 状态脊、圆点、游标条高度用 `@ScaledMetric(relativeTo: .footnote)` 跟随字号缩放。
- 只有图表坐标轴标签允许用 `.dynamicTypeSize(...DynamicTypeSize.accessibility2)` 限制上限，正文不限制。

### 4.1 圆角体系

| 令牌 | 值 | 用途 | 实现 |
|---|---|---|---|
| `Radius.bar` | 1pt | 游标条、图表柱（柱子 1.5pt） | `RoundedRectangle(cornerRadius:style: .continuous)` |
| `Radius.lamp` | 3pt | 灯牌（近直角，像仪表铭牌） | 同上 |
| `Radius.control` | 8pt | 筛选条选项、输入框、行内小按钮 | 同上 |
| `Radius.panel` | 14pt | 概览、详情页的面板 | 面板上设置 `.containerShape(.rect(cornerRadius: 14))`，内部元素用 `ConcentricRectangle()` 自动同心（内边距 8 时内角为 6）【已验证 iOS 26】 |
| 控件坞 | 与屏幕圆角同心，最小 18pt | 批量选择坞 | `ConcentricRectangle(corners: .concentric(minimum: .fixed(18)), isUniform: true)`【已验证】 |

| 页面类型 | 结构 | 背景 |
|---|---|---|
| **列表页**（账号、日志、用户、分组） | `List` + `.listStyle(.plain)`，满宽行，行间发丝线 | 整页 `panel`（`.scrollContentBackground(.hidden)` + `.background(panel)`） |
| **仪表板页**（概览、账号详情、用户详情） | `ScrollView` + 面板模块：刻度线标头在面板**外**，面板内放读数 | 页面 `canvas`，面板 `panel`，面板外缘 1 物理像素 `hairline` 描边 |

## 5. Liquid Glass 用法

### 5.1 系统玻璃（自动获得，不加修饰）

| 位置 | 实现 |
|---|---|
| Tab 栏（iPad 可变侧栏） | `TabView` + `Tab(...)`，`.tabViewStyle(.sidebarAdaptable)` |
| 导航栏按钮：站点切换、筛选、更多 | `toolbar`；站点切换用 `toolbarTitleMenu` 或 leading `Menu` |
| 搜索 | `Tab(role: .search)` + `.tabViewSearchActivation(.searchTabSelection)`（见 03 §1.1） |
| 详情页底部动作 | `.safeAreaBar(edge: .bottom)` + `GlassEffectContainer` + `.buttonStyle(.glass)`；主动作用 `.glassProminent` |
| sheet、菜单、上下文菜单、确认对话框、开关和滑块 | 系统 |
| “有 N 条待核对”的持久提示 | `.tabViewBottomAccessory(isEnabled:)`（iOS 26.1） |

### 5.2 自定义 `.glassEffect`：只有两处

| # | 组件 | 写法 | 理由 |
|---|---|---|---|
| 1 | **控件坞 `ControlDock`**：账号批量选择时的底部条（标题栏显示“已选 3 个账号”，坞内放“停止调度 / 启用调度 / 更多”） | 一个整体玻璃形状：`.glassEffect(.regular.interactive(), in: ConcentricRectangle(...))`；**内部按钮不用玻璃样式**（`.borderless`，主动作用实心 `.borderedProminent` + `signalFill`），避免玻璃叠玻璃（WWDC25-323：“glass can not sample other glass”） | 批量动作是一组，应由一个控件承载 |
| 2 | **操作回执胶囊 `ResultCapsule`**：“已停止调度 · 撤销”，3–5 秒后收起 | `.glassEffect(.regular.interactive(), in: .capsule)`；对勾用 SF Symbols 7 的 `.symbolEffect(.drawOn)`（iOS 26【已验证】） | 浮在内容之上的瞬时控件 |

不用自定义玻璃的地方：指标卡、列表行、面板、灯牌、图表、筛选条（筛选条用 `.safeAreaBar(edge: .top)` 承载，选项本身是不透明的 `inset` / `signalWash` 底）。

### 5.3 tint 规则

1. 全局 `.tint(signal)`：Tab 选中项、链接、开关的开启色。
2. 玻璃上只允许一种 tint：**主动作**的 `.glassProminent.tint(signalFill)`，每屏最多一个。
3. **绝不**给玻璃加状态色：没有红色玻璃按钮、绿色玻璃胶囊。破坏性动作在菜单里用 `role: .destructive` 的红字。
4. 工具栏图标保持系统单色。筛选生效用 `.badge(n)` 表示（iOS 26 工具栏支持），不用 tint。

### 5.4 与内容的分离

- 内容层全部不透明。滚动边缘用系统默认的 `.scrollEdgeEffectStyle(.soft, for:)`；筛选条用 `safeAreaBar`，可参与边缘效果。
- **深浅色**：浅色下玻璃叠在白色 `panel` 上，深色下叠在 `#15191C` 上。图表数据是中性石墨色，不会像现状的品红柱子那样把玻璃底栏染色（05 §4.9）。状态脊只有 3pt 宽，滚到 Tab 栏下面时着色面积可以忽略。
- **降低透明度**（`accessibilityReduceTransparency`）：两个自定义玻璃组件退化为 `panel` 底 + 1pt `hairline` 描边（已写进组件代码）。系统玻璃由系统处理。
- **iOS 27**：用户可以在系统里调节 Liquid Glass 的透明度和色调（03 §0.3）。本方向的可读性不依赖玻璃，内容层不透明，所以不受影响；验收时需在 iOS 26 和 27 上各截一次图。

### 6.1 SF Symbols 用法

### 6.4 App 图标概念

## 7. 数据可视化（Swift Charts）

### 7.1 原则

1. **结论先行**：图表标题行直接写读数（“今日实际 $1,284.50 · 较昨日同时 ▲ 8.2%”），单位写进标题（HIG Charts）。
2. **数据中性，选中用信号青，阈值用语义色**。
3. **不要求交互才能读到关键信息**；交互只用于查看单点。

### 7.2 配色与线型

| 用途 | 颜色 | 线型 / 形状 |
|---|---|---|
| 单系列柱（已完成时段） | `rule`（`#7F898F` / `#606A71`） | 柱宽 `.ratio(0.62)`，圆角 1.5 |
| 单系列柱（当前未完成时段） | `ink1` | 同上，提示“进行中” |
| 选中柱 / 选中线 | `signal` / `signal.lamp` | 1pt 竖线 `RuleMark` |
| 趋势线 | `ink2` | 1.5pt，`.interpolationMethod(.monotone)` |
| 成本三口径 | 见第 2.5 节 | 实线 / 虚线 / 点线 |
| 阈值 | 对应语义 `lamp` | 1pt `[3,3]` 虚线 + 右上角文字（“阈值 5%”） |
| 分类数据（Token 构成、模型占比、分组占比） | **石墨明度阶**：`ink1` → `ink2` → `rule` → `inset` 加深一档，按占比从大到小排列；超过 4 类合并为“其他” | 每段带文字标签，不依赖图例 |
| 缺失时段（站点未返回） | 不画柱，基线上画 2pt `rule` 短刻度 | 读者能看出“有缺口”而不是“为 0” |

### 7.3 线宽、网格、坐标轴

- y 轴：放在右侧（`AxisMarks(position: .trailing)`），3 个刻度（`desiredCount: 3`），网格线 0.5pt `hairline`，**不画竖向网格**。
- x 轴：只画 4pt 短刻度（`AxisTick(length: 4)`，`rule` 色），像尺子刻度；标签 `caption2` 等宽数字，`ink3`；按 6 小时或 7 天步进，避免现状“每根柱子都有标签”（01 D27）。
- 柱状图 y 轴从 0 开始。
- 图表区背景 `panel`（`.chartPlotStyle`），不加边框。

### 7.4 选中态：固定读数窗

`chartXSelection(value:)`（iOS 17【已验证】）让整个绘图区都可选择。选中后：
- 绘图区出现 1pt `signal.lamp` 竖线，被选中的柱变为 `signal`；
- **标题行的读数原地换成选中值**（“14:00–15:00 · 实际 $86.20”），并用 `.contentTransition(.numericText(value:))` 过渡；松手 2 秒后恢复汇总值。
- 不弹浮层，不遮挡数据，也不会出现溢出问题。这就是“固定读数窗”。
- 详细明细仍通过“逐小时明细”列表提供，作为 VoiceOver 的替代路径。

### 7.5 迷你趋势（sparkline）

- 高 20pt，线宽 1.25pt，颜色 `ink2`；如果该指标当前处于琥珀或红区间，线改用对应 `lamp`。
- 不画坐标轴和图例；末点不加圆点（避免与状态圆点混淆）。
- `accessibilityHidden(true)`，所在行的读数已经提供了文字。

### 7.6 容量与配额：游标条

| 规格 | 值 |
|---|---|
| 高度 | 6pt（`@ScaledMetric(relativeTo: .footnote)`） |
| 轨道 | `inset`，圆角 1pt |
| 刻度切口 | 25/50/75% 处各 1pt，颜色为 `panel`（看起来像刻在轨道上） |
| 填充 | <75% 为 `ink2`（中性石墨，暗座舱）；≥75% 琥珀 lamp；≥90% 红 lamp（阈值与 Web `UsageProgressBar` 一致） |
| 越限 | 值 >100% 时填满，右端加 2pt 红色“越限帽” |
| 缺失 | 只画轨道，读数显示“—” |
| 读数 | 右侧 `readoutS` “2/4” + `unit` “并发” |
| 列表 | 只显示最紧张的一项；详情页列出全部（并发、RPM、日 / 周 / 总配额、5 小时窗口） |
| 色弱 | 开启“区分时不仅依赖颜色”时，≥75% 的读数后追加“!”字符，≥90% 追加“!!” |

### 7.7 健康分刻度尺

0–100 横向刻度尺：每 10 分一个短刻度，60 和 90 处为长刻度并标数字（Web 阈值：≥90 健康、60–89 风险、<60 异常、无流量为待机）。当前值用 2pt 竖向指针表示，颜色按区间取正常、琥珀或红；右侧 `readoutL` 显示数值，后接“健康 / 风险 / 异常 / 待机”文字。数据来自 `ops/dashboard/overview` 的 `health_score`（02 §5，原生端已接入 overview 接口但只取了两个字段）。

### 7.8 可访问性

- 每张图提供 `accessibilityChartDescriptor`，或者“明细列表”替代路径（保留现有做法，01 §7）。
- 系列区分永远是“颜色 + 线型”，单系列图不依赖颜色。

## 8. 动效与触觉

### 8.1 动效词汇

| 场景 | 动画 | 时长 |
|---|---|---|
| 按压反馈 | 系统 | — |
| 状态灯牌切换 | `.contentTransition(.symbolEffect(.replace))` + 文字交叉淡入淡出 | `Motion.quick` 0.18s snappy |
| 行进入 / 离开、筛选结果更新 | 透明度 + 4pt 位移，不做大幅滑入 | `Motion.standard` 0.25s snappy |
| 面板展开（如待处理展开全部） | 高度展开 | `Motion.settle` 0.35s smooth |
| 新出现的错误或过载 | 行首图形 `.symbolEffect(.bounce, value:)` **只弹一次** | 系统 |
| 循环动画 | **不使用**。仪表灯常亮不闪，省电，也不分散注意力 | — |

### 8.2 数字、刷新、倒计时

- **数字滚动**：刷新后读数变化用 `.contentTransition(.numericText(value:))`（iOS 17【已验证】），放在 `withAnimation(Theme.Motion.standard)` 里。
- **刷新**：整页只用系统 `.refreshable`，不在每个面板放刷新按钮和转圈（01 D19）。新鲜度只在导航副标题出现一次（“刚刚更新”，`navigationSubtitle`，iOS 26【已验证】）。数据超过 5 分钟未更新时，这几个字改为琥珀 ink。
- **首次加载**：`.redacted(reason: .placeholder)` 骨架，**不加闪光动画**。
- **倒计时**：详情页用 `Text(timerInterval: now...resetAt, countsDown: true)`（iOS 16【已验证】），按秒跳动；列表用 `Text(.currentDate, format: .reference(to: resetAt))`（iOS 18【已验证】），按分钟更新，避免多行同时跳秒造成噪声。

### 8.3 sensoryFeedback 映射（`Theme.feedback(_:)`）

| 事件 | 例子 | `SensoryFeedback` |
|---|---|---|
| 提交成功 | 启用调度、恢复状态、充值成功、退款成功 | `.success` |
| 可撤销的单对象停止类操作 | 停止调度、标记错误已处理（配回执胶囊和“撤销”） | `.impact(weight: .medium)` |
| 撤销 | 点击回执上的“撤销” | `.impact(flexibility: .soft)` |
| 明确失败 | 服务器拒绝、校验失败 | `.error` |
| 结果待核对 | 写请求结果不明 | `.warning` |
| 选择变化 | 筛选条、分段、批量勾选 | `.selection` |
| 刷新后待处理数上升 | 首页“错误账号”从 1 变 3 | `.increase`（“重要数值越过显著阈值”的语义） |
| 账号测试开始 / 结束 | 流式测试 | `.start` / `.stop`【推断：iPhone 上的实际触感需真机确认】 |
| 资金确认 | 充值确认按钮 | 不额外加（系统对话框自带反馈），避免把资金操作做得“轻快” |

以上成员均为 iOS 17 API【已验证】。iOS 26 新增的 `press(_:)`/`release(_:)` 暂不使用。

### 8.4 减弱动态效果（`accessibilityReduceMotion`）下的替代

| 原效果 | 替代 |
|---|---|
| 数字滚动 | 直接替换（`.contentTransition(.identity)`） |
| 符号弹跳、`drawOn` | 关闭，图标直接出现 |
| 位移类转场 | 只保留透明度 |
| 秒级倒计时 | 详情页改为“4 分钟后恢复”，按分钟更新 |
| 图表选中 | 无动画；读数窗直接切换 |

## 10. SwiftUI 设计令牌代码

下面是完整的 `Theme.swift`，可直接放进 `NativeApp/Views/`。它已通过第 0 节所述的 Swift 6 严格并发类型检查。

要点：
- SwiftUI **没有** `Color(light:dark:)` 初始化器（Apple 文档 404，编译器报 `extra argument 'dark'`）【已验证】。本文用 `UIColor(dynamicProvider:)` 同时解析浅色、深色和增强对比度。`UIColor`、`UITraitCollection`、`Color`、`Font`、`EdgeInsets`、`StrokeStyle`、`Animation`、`SensoryFeedback` 都是 `Sendable`【已验证】，所以静态常量在 Swift 6 下合法。
- 状态判定（优先级同 Web `AccountStatusIndicator`）应放在 `Sub2Core`，视图层只把判定结果 `AccountLamp` 映射为样式。

```swift
// Theme.swift — 「游标 Vernier」视觉方向设计令牌
// 目标：iOS 26+，Swift 6 语言模式 + SWIFT_STRICT_CONCURRENCY=complete。
// SwiftUI 没有 Color(light:dark:)；这里用 UIColor(dynamicProvider:) 同时解析
// 浅色 / 深色 / 增强对比度（UIAccessibilityContrast.high）四种外观。
import SwiftUI
import UIKit

enum Theme {}

extension Theme {
    struct Swatch: Sendable {
        let light: UInt32
        let dark: UInt32
        let lightHigh: UInt32
        let darkHigh: UInt32

        init(_ light: UInt32, _ dark: UInt32) {
            self.init(light, dark, light, dark)
        }

        init(_ light: UInt32, _ dark: UInt32, _ lightHigh: UInt32, _ darkHigh: UInt32) {
            self.light = light
            self.dark = dark
            self.lightHigh = lightHigh
            self.darkHigh = darkHigh
        }

        var uiColor: UIColor {
            let swatch = self
            return UIColor { traits in
                let isDark = traits.userInterfaceStyle == .dark
                let isHigh = traits.accessibilityContrast == .high
                let hex: UInt32
                if isDark {
                    hex = isHigh ? swatch.darkHigh : swatch.dark
                } else {
                    hex = isHigh ? swatch.lightHigh : swatch.light
                }
                return Theme.rgb(hex)
            }
        }

        var color: Color { Color(uiColor: uiColor) }
    }
}

extension Theme {
    static func rgb(_ hex: UInt32) -> UIColor {
        UIColor(
            red: CGFloat((hex >> 16) & 0xFF) / 255,
            green: CGFloat((hex >> 8) & 0xFF) / 255,
            blue: CGFloat(hex & 0xFF) / 255,
            alpha: 1
        )
    }

    /// 中性色与信号色。语义状态色见 Theme.Tones。

    }

// MARK: - 动效与触觉

extension Theme {
    enum Motion {
        static var quick: Animation { .snappy(duration: 0.18) }
        static var standard: Animation { .snappy(duration: 0.25) }
        static var settle: Animation { .smooth(duration: 0.35) }
    }

    enum HapticEvent: Sendable {
        case committed        // 启用调度、恢复状态、充值/退款成功
        case reversibleStop   // 停止调度等可撤销单对象操作
        case undone           // 点“撤销”
        case rejected         // 服务器明确拒绝
        case uncertain        // 结果待核对
        case selection        // 筛选、分段、选择模式勾选
        case anomalyRose      // 刷新后异常数上升
        case testStarted
        case testFinished
    }

    static func feedback(_ event: HapticEvent) -> SensoryFeedback {
        switch event {
        case .committed: return .success
        case .reversibleStop: return .impact(weight: .medium)
        case .undone: return .impact(flexibility: .soft)
        case .rejected: return .error
        case .uncertain: return .warning
        case .selection: return .selection
        case .anomalyRose: return .increase
        case .testStarted: return .start
        case .testFinished: return .stop
        }
    }
}

// MARK: - 账号状态 → 灯牌（判定逻辑在 Sub2Core；优先级与 Web AccountStatusIndicator 一致）

enum AccountLamp: Equatable, Sendable {
    case normal
    case paused                         // schedulable == false
    case inactive                       // inactive / disabled
    case rateLimited(resetAt: Date)     // 429
    case overloaded(until: Date)        // 529
    case tempUnschedulable(until: Date?)
    case quotaExceeded
    case error
    case unknown
}

struct LampSpec: Sendable {
    let title: String
    let symbol: String
    let tone: Tone
    let showsSpine: Bool
}

extension Theme {
    static func lamp(_ state: AccountLamp) -> LampSpec {
        switch state {
        case .normal:
            return LampSpec(title: "正常", symbol: "circle.fill", tone: .normal, showsSpine: false)
        case .paused:
            return LampSpec(title: "暂停", symbol: "pause.circle.fill", tone: .idle, showsSpine: false)
        case .inactive:
            return LampSpec(title: "停用", symbol: "minus.circle.fill", tone: .idle, showsSpine: false)
        case .rateLimited:
            return LampSpec(title: "限流中", symbol: "hourglass", tone: .caution, showsSpine: true)
        case .overloaded:
            return LampSpec(title: "过载中", symbol: "flame.fill", tone: .fault, showsSpine: true)
        case .tempUnschedulable:
            return LampSpec(title: "临时不可调度", symbol: "clock.badge.exclamationmark", tone: .caution, showsSpine: true)
        case .quotaExceeded:
            return LampSpec(title: "配额超限", symbol: "gauge.with.dots.needle.100percent", tone: .caution, showsSpine: true)
        case .error:
            return LampSpec(title: "错误", symbol: "xmark.octagon.fill", tone: .fault, showsSpine: true)
        case .unknown:
            return LampSpec(title: "未知", symbol: "questionmark.circle", tone: .idle, showsSpine: false)
        }
    }

    /// 附加标签：模型级限流（紫），与主状态并列显示。
    static func modelLimitTag(count: Int) -> LampSpec {
        LampSpec(title: "模型限流 \(count)", symbol: "cube.fill", tone: .model, showsSpine: false)
    }

    /// 容量 / 配额阈值（与 Web 一致：≥90% 红，≥75% 琥珀，其余中性石墨）。
    static func capacityFill(_ fraction: Double) -> Color {
        if fraction >= 0.9 { return Tones.fault.lamp }
        if fraction >= 0.75 { return Tones.caution.lamp }
        return Palette.ink2
    }
}

/// 游标条：容量 / 配额。fraction 为 nil 表示站点未返回（只画轨道）。
struct VernierBar: View {
    let fraction: Double?
    var ticks: [Double] = [0.25, 0.5, 0.75]
    @ScaledMetric(relativeTo: .footnote) private var height: CGFloat = Theme.Metric.vernier

    var body: some View {
        GeometryReader { proxy in
            let width = proxy.size.width
            let value = fraction ?? 0
            let clamped = min(max(value, 0), 1)
            ZStack(alignment: .leading) {
                Rectangle().fill(Theme.Palette.inset)
                if fraction != nil {
                    Rectangle()
                        .fill(Theme.capacityFill(value))
                        .frame(width: width * clamped)
                }
                ForEach(ticks, id: \.self) { tick in
                    Rectangle()
                        .fill(Theme.Palette.panel)
                        .frame(width: 1)
                        .offset(x: width * tick)
                }
                if value > 1 {
                    Rectangle()
                        .fill(Theme.Tones.fault.lamp)
                        .frame(width: 2)
                        .offset(x: width - 2)
                }
            }
        }
        .frame(height: height)
        .clipShape(RoundedRectangle(cornerRadius: Theme.Radius.bar, style: .continuous))
        .accessibilityHidden(true)
    }
}

/// 读数：数值（ink1，等宽数字）+ 单位（ink3，小一级）。
struct Readout: View {
    let value: String
    var unit: String? = nil
    var font: Font = Theme.Typeface.readoutM

    var body: some View {
        HStack(alignment: .firstTextBaseline, spacing: 3) {
            Text(value)
                .font(font)
                .foregroundStyle(Theme.Palette.ink1)
            if let unit {
                Text(unit)
                    .font(Theme.Typeface.unit)
                    .foregroundStyle(Theme.Palette.ink3)
            }
        }
        .lineLimit(1)
    }
}

/// 控件坞：批量操作条等悬浮控件。全 App 自定义 .glassEffect 的两处之一。
struct ControlDock<Content: View>: View {
    @ViewBuilder var content: Content
    @Environment(\.accessibilityReduceTransparency) private var reduceTransparency

    private var shape: ConcentricRectangle {
        ConcentricRectangle(corners: .concentric(minimum: .fixed(Theme.Radius.dockMinimum)), isUniform: true)
    }

    var body: some View {
        let row = HStack(spacing: Theme.Space.s) { content }
            .padding(.horizontal, Theme.Space.m)
            .padding(.vertical, Theme.Space.s)
        if reduceTransparency {
            row
                .background(Theme.Palette.panel, in: shape)
                .overlay(shape.stroke(Theme.Palette.hairline, lineWidth: 1))
        } else {
            row.glassEffect(.regular.interactive(), in: shape)
        }
    }
}

extension View {
    /// 根视图：信号青作为全局 tint；中文排版。
    func vernierRoot() -> some View {
        self
            .tint(Theme.Palette.signal)
            .typesettingLanguage(Locale.Language(identifier: "zh-Hans"))
    }

    /// 列表行：状态脊 + 统一内边距 + 不透明面板底。
    func vernierRow(spine: Tone?) -> some View {
        self
            .listRowInsets(Theme.Space.rowInsets)
            .listRowBackground(
                HStack(spacing: 0) {
                    Rectangle()
                        .fill(spine.map { Theme.style($0).lamp } ?? Color.clear)
                        .frame(width: Theme.Metric.spine)
                    Theme.Palette.panel
                }
            )
            .listRowSeparatorTint(Theme.Palette.hairline)
    }
}
```

## 11. 风险与对策

| # | 风险 | 表现 | 对策 |
|---|---|---|---|
| 1 | **可读性：灰阶过淡** | 三级文字、单位、坐标轴在户外强光下看不清 | 三级文字也按 ≥4.5:1 设计（浅色 `ink3` 对 panel 为 5.70）；`hairline` 不承载信息；增强对比度模式下整体降一档（第 2.7 节）；关键读数一律 `ink1` |
| 2 | **暗座舱被误读为“没加载”** | 正常时页面几乎没有颜色，管理员不确定是全部正常还是数据没出来 | 待处理面板为 0 时显式写“全部正常 · 46 个账号可调度 · 近 1 小时无新错误”；导航副标题常驻新鲜度；首次加载用骨架而不是空白 |
| 3 | **风格偏冷、工程感重** | 用户觉得“像监控软件不像产品” | 个性来自窄体读数、游标条、状态脊、App 图标和信号青；保留系统动效与触觉的手感；如果需要更“暖”，只调中性色的色相（例如 200° → 40° 暖石墨），不改语义色 |
| 4 | **玻璃叠加** | 自定义坞里放玻璃按钮造成玻璃叠玻璃；彩色内容滚到底栏下把玻璃染色 | 自定义玻璃限两处，内部按钮不用玻璃样式（已写进示例）；图表数据为中性色；降低透明度时退化为实底 + 描边；验收时在 iOS 26 和 27 的浅色、深色、清透外观下各截一次图 |
| 5 | **控件过多叠在底部** | Tab 栏 + 详情动作栏 + 回执胶囊同时出现，底部拥挤 | 回执胶囊出现在动作栏上方，3–5 秒后收起；批量模式下用 `ControlDock` 替代动作栏；“待核对”使用 `tabViewBottomAccessory`，不与胶囊同时出现 |
| 6 | **中文排版** | 苹方没有 Bold；窄体或 Mono 与中文混排时对不齐；行高偏紧 | 只用 Regular、Medium、Semibold；读数拆成“数字 Text + 中文单位 Text”；Mono 只给 ASCII；根视图设置 `typesettingLanguage(zh-Hans)`；中西文之间手动加空格 |
| 7 | **Dynamic Type 大字号** | 窄体主读数在 AX5 下超宽；四列读数格挤爆；行高超过一屏 | 主读数用 `ViewThatFits` 退化为紧凑格式（`$1.28K`）；读数格 4 → 2 → 1 列；辅助功能字号下列表隐藏元信息行；不用 `minimumScaleFactor`；坐标轴标签上限 `accessibility2` |
| 8 | **色弱** | 琥珀与红、琥珀与成本橙、绿与青难以区分 | 已按 CVD 模拟调整琥珀和红（绿色盲下 ΔE 从 4.0 提到 15.4）；状态永远是“形状 + 文字 + 颜色”；成本系列有线型；开启“区分时不仅依赖颜色”后容量读数追加 `!`/`!!` |
| 9 | **语义色被挪用** | 后续开发随手用绿色表示“收入”、用紫色表示“输出 Token” | `Tone` 只有 6 个枚举值；分类图表强制用石墨明度阶；在 PR 检查清单中加一条“新增颜色必须来自 Theme” |
| 10 | **绿色一色两用**（正常 / 实际扣费） | 读者把“实际”的绿线误读为“正常” | 实际扣费只以图例刻度和实线出现，金额文字永远 `ink1`；状态绿只以圆点和对勾出现，两者形态不重叠 |
| 11 | **与 Web 配色不一致** | 平台色、错误类型色、Token 构成色在 App 中消失，熟悉 Web 的管理员需要适应 | 文字标签与 Web 完全一致（04 §4.1）；只去掉了不属于简报语义的装饰色；在帮助页的“颜色说明”里写明 |
| 12 | **系统更新** | iOS 27.x 继续调整 Liquid Glass 和列表行高 | 内容层不依赖系统列表的默认行高（统一 `rowInsets`）；令牌集中在一个文件里，便于整体调整 |
